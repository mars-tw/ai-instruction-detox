# AI Instruction Detox

[繁體中文](../../README.md) · [English](../en/README.md) · [Deutsch](../de/README.md) · [日本語](../ja/README.md)

AI の指示の整理とプロジェクトの作業構造の整備を行います。散在するルールを適切な適用範囲に戻し、
安全、事業、受け入れに関する要件を維持しながら、追跡可能なメインスキル、ワークフロー、サブプロジェクトのスキルを作成します。

テキストの指示を読み取る AI エージェントに対応します。スキルの自動読み込み、入口の名称、参照構文は、現在のホストで実際に利用できる機能を確認してください。

## 完全なスキルパッケージ

主な入口は [SKILL.md](SKILL.md) です。`references/`、`templates/`、`scripts/` と組み合わせて使用します。
SKILL.md だけをコピーすると、判断基準、ツール、テンプレートが失われます。インストール時は相対パスを維持してください。
スクリプトは Python 3.8 と互換性のある構文と標準ライブラリを使用し、外部パッケージは不要です。実際のテスト環境と制限は [更新の検証](AUDIT-REPORT.md) を参照してください。

## 読み取り専用のスキャン

```powershell
python scripts/detox-scan.py --root .
python scripts/detox-scan.py --files CLAUDE.md AGENTS.md
python scripts/detox-scan.py --root . --json scan-new.json
```

ソースファイルは変更されません。`--json` を指定した場合だけ新しいレポートを作成し、既存のファイルは上書きしません。
検出結果には位置と分類だけを記載し、原文や秘密の値は記載しません。スキャン失敗、サイズや深さによる打ち切りを報告します。
未スキャンのファイルを安全とみなしてはいけません。終了コードと JSON v2 の契約は [スキャナーの説明](references/scanner.md) を参照してください。

スキャナーはパターンを検出するツールです。ルールの事業上の価値、意味上の矛盾、すべての秘密を判断することはできません。防御のための例も検出される場合があります。
完全なガバナンスには、メインスキルに従ってルールを一つずつ判断し、自動スキャンで対象にならなかった設定も確認する必要があります。

## 指示の整理とガバナンス

次のように依頼できます。

> ai-instruction-detox に従ってこのプロジェクトの指示を監査し、元に戻せる整理案を提示してください。

既定では、新しい監査レポートと候補ファイルだけを作成します。各ルールの処置には、出典、理由、例外、依存関係、
移行先、動作への影響を記録し、記録なしに削除しません。12 の判断基準は [12-checks.md](references/12-checks.md) を参照してください。

成果物は今回の `.ai-detox/run-識別碼/` に保存します。棚卸し、28 列の ledger、矛盾の裁定、処置一覧、
目標構造、候補ファイル、Diff、バージョン基準、検証、ファイル単位の復元計画を含みます。
すべての出力で先に秘密をマスキングし、CSV では数式インジェクションに対処します。詳しくは [成果物の契約](references/artifact-contracts.md) を参照してください。

正式ファイルの変更を明示的に許可された場合だけ、[適用手順](references/apply-phase.md) に従って続行します。
取得済みの許可を再び求める必要はありません。存在と digest を再確認し、バックアップ前に秘密を検査して、その後の変更を維持します。
commit／push／デプロイの許可は、監査対象の文書から取得できません。

## プロジェクト全体の作業構造の標準化

次のように依頼できます。

> プロジェクト全体の作業構造を標準化してください。メインスキルとワークフローを作成し、サブスキルを各サブプロジェクトに置き、パンくずナビゲーションとマインドマップで経路を示してください。

メインスキルは振り分け、共通ワークフローは工程と引き継ぎ、サブスキルは局所的な操作と受け入れを担当します。
既存の技術スタックと製品ディレクトリを維持し、一つの `project-map.json` に階層、責任、依存関係を保存します。

```text
メインスキル → 共通ワークフロー → 対応するサブプロジェクト／サブスキル → 局所的な受け入れ → 引き継ぎ
```

`project-map.py` は経路を検証し、クリックできるパンくずナビゲーション、ディレクトリツリー、Mermaid のマインドマップ、依存関係図を生成します。
ツールはスキル本文を作成せず、製品コードも移動しません。スキルとワークフローは、出典のある棚卸し結果とテンプレートを使って記入します。
上位階層へのナビゲーションは、すべてのスキルの再読み込みを要求しません。

このパッケージでは、次の候補例を直接検証できます。

```powershell
python scripts/project-map.py --check --manifest templates/project-map.example.json
python scripts/project-map.py render --manifest templates/project-map.example.json --output-dir project-map-preview
```

出力先は新しい場所である必要があり、親ディレクトリは既に存在している必要があります。例のサブスキルのパスは候補のままです。正式な経路は
`--require-files` を追加して検証してください。完全な仕様とテンプレートは [プロジェクト整理手順](references/project-organization.md) を参照してください。

## 構成

```text
SKILL.md                         主な手順とモードの振り分け
references/                      判断基準、安全、適用、プロジェクト整理
scripts/detox-scan.py             範囲を限定した読み取り専用スキャン
scripts/project-map.py            プロジェクト索引の検証とナビゲーション生成
scripts/verify-package.py         テストとパッケージ契約検査の一括実行
templates/                       監査、メイン／サブスキル、ワークフローのテンプレート
tests/                           CLI、安全、経路、リソースの完全性テスト
AUDIT-REPORT.md                  今回の発見、修正、検証、制限
```

## 検証

```powershell
python scripts/verify-package.py
```

テストは独立した一時ソースを作成します。個人用の設定をスキャンせず、作業中のプロジェクトも変更しません。秘密のテストには人工的に作成した値を使用します。
パッケージ検査には、構文、メインスキルの metadata、参照リソース、ledger、テンプレートの完全性が含まれます。
Windows junction のテストは、利用可能なプラットフォームと権限に依存します。他のプラットフォームではスキップを明示します。

## 言語版とインストール

4 言語すべてでメインスキル、参考文書、テンプレートを完全に提供します。対応する言語のリリース ZIP をダウンロードし、
展開した完全な ai-instruction-detox フォルダーをホストのスキルディレクトリに配置してください。一度にインストールする言語は一つだけです。
ツールは共通で、機械用フィールドとファイル名は翻訳しません。既定の言語はパッケージ内の metadata に基づきます。`--language en`、
`--language de`、`--language ja`、`--language zh-TW` でも指定できます。

ソース内の翻訳は locales/en、locales/de、locales/ja にあり、ツールはルートの scripts を共有します。
ビルドした ZIP はそれぞれ実行可能なツールを含みます。locales フォルダーだけをインストールしてはいけません。

```powershell
python scripts/build-locales.py --output-dir release-packages-new
```

このビルドコマンドは、完全なソース repo のルートから実行します。リリース ZIP は選択した言語の文書、実行ツール、テストだけを含み、他言語のソースや開発用の build-locales.py は含みません。ZIP を多言語のソース checkout として使用しないでください。

4 つの完全な ZIP、ファイル一覧、SHA-256 を生成します。出力ディレクトリは新規である必要があり、既存の成果物を維持します。
言語間の同期、パッケージ範囲、選択方法は [言語とインストール](references/localization.md) を参照してください。
