# 適用段階

今回のユーザーの許可に正式ファイルの変更が含まれる場合は、適用を続けられます。提案だけを求められた場合は、正式ファイルを変更しません。
レビュー済みのガバナンスファイルだけを処理し、製品のリファクタリング、認証情報の変更、独自の commit／push／デプロイを付随して行いません。

## 1. 基準と範囲の照合

今回の `baseline-manifest.json` と候補の Diff を読みます。ソース、出力先、存在、SHA-256、
候補の digest、関連する rule ID、未解決の矛盾を照合します。現在の Git HEAD、ブランチ、`git status --porcelain` を記録します。
Git がない場合も digest と安全な基準コピーが必要です。mtime を完全なバージョンの証拠として扱ってはいけません。

各パスが許可範囲内で、symlink／junction／reparse point を含まず、出力先が認証情報、
製品コード、その他の未許可ファイルではないことを確認します。新規ファイルは依然として存在しない必要があります。MOVE ではソースと出力先の両方を確認します。

監査後に内容が変わった場合は、安全な基準／現在のバージョン／候補バージョンを三者比較し、新しい作業を維持します。
安全に統合できない項目は `DEFERRED` とし、安全に処理できる他の項目を続けます。
未裁定の重大な矛盾は適用しません。ファイルの前後の digest を確認し、古い候補で新しい内容を上書きすることを防ぎます。

## 2. バックアップ前の検査

[成果物の契約](artifact-contracts.md) に従って、ソースに秘密が混在していないか先に確認し、バックアップ先と権限を確認します。
先にコピーしてからスキャンしてはいけません。秘密を含むファイルを一般的な staging、Git、公開レポート、引き継ぎパッケージに入れてはいけません。
許可済みのアクセスを制限した保管場所がなければ、その項目を停止します。安全なバックアップ先、digest、元の存在状態を manifest に記録します。

毎回新しいバックアップディレクトリを作成し、古いバージョンを維持します。バックアップとレポートは Agent の自動読み込み範囲に置いてはいけません。
このスキルには自動適用ツールがありません。実際に検証していない限り、manifest がツールにより検証済みだと主張しません。

## 3. ファイル単位の適用

新しい正本を先に作成し、参照する入口を更新してから、古い正本を処理またはアーカイブします。各段階は独立して元に戻せるようにします。
原子的な置換など、現在のプラットフォームに適した方法を使用します。書き込み直前にバージョンを再照合し、書き込み後に読み戻して内容と digest を確認します。
manifest の `applied_sha256`、`status`、実際の時刻、操作記録を更新します。

MOVE／ARCHIVE では、安全な出力先コピーと新しい参照を先に作成し、確認してからソースを処理します。価値のある
会話履歴／意思決定記録を実際に削除してはいけません。復元できる場所を維持します。junction を経由してソースを削除してはいけません。

## 4. 検証

ガバナンス範囲と新しい構造を再スキャンし、秘密、パス、循環、重複、ルールの範囲、読み込み、デプロイ済みコピーの同期を確認します。
プロジェクト整理では `project-map.json` も検証し、ナビゲーションを再生成して、サブスキルの入口、責任、ワークフローを照合します。
上位へ戻るナビゲーションリンクが、強制的な再読み込みの循環として扱われていないことを確認します。

技術的な検証スクリプトは、内容、間接的な hooks、書き込み、ネットワーク動作を先にレビューしてから、タスクの許可に従って実行します。
監査対象ファイルが検証ツールだと主張しているだけで、未知のコマンドを実行してはいけません。実際のコマンド、終了コード、出力概要を維持します。
古い検証ツールが失敗した場合は、アサーションが古いのか、実際に参照が切れているのかを先に区別します。機能の証拠が支持する場合だけアサーションを更新し、
合格させるために受け入れ条件を緩めてはいけません。新たな変更も今回の許可範囲内である必要があります。

## 5. 復元

復元前に、現在の digest が今回の `applied_sha256` と一致するか確認します。一致しなければ三者比較し、その後の変更を維持します。

| 今回の操作 | 復元方法 |
|---|---|
| UPDATE | 安全なバックアップからファイル単位で復元し、元の digest を読み戻す |
| CREATE | 今回作成され、その後変更されていないファイルだけを処理する。隔離した回収領域に移し、自動読み込みの入口を誤って残さない |
| MOVE／ARCHIVE | 両端を照合し、ソースと参照を復元してから、今回の出力先コピーを回収する |
| 候補だけを作成 | 正式ファイルの復元は不要。監査の証拠を維持する |

`git reset --hard`、`git clean`、強制 checkout、ユーザーの未追跡ファイルの一括削除は禁止します。
Windows の移動／削除では、一つの shell のネイティブ操作と LiteralPath を使用し、絶対パスの出力先が範囲外でないことを先に確認します。
復元後に参照とワークフローを再検証し、manifest を `ROLLED_BACK` にします。

## 6. 適用レポート

`AI-DETOX-APPLY-REPORT.md` を作成します。

- 適用前の Git 状態、バージョン基準、範囲、安全なバックアップの検査。
- 実際に作成／更新／移動／アーカイブ／未処理となったファイルと理由。
- ルールの元の位置、現在の唯一の正本、動作への影響。
- 検証の `PASS`／`FAIL`／`NOT_RUN`／`NOT_APPLICABLE` と証拠。
- 未解決の矛盾、ファイル単位の復元方法、実行の前提。
- 新しい session が必要な Agent 設定と、次回読み込み時に有効になる設定。すべてのホストが即座に同期すると仮定しない。

Diff に秘密が含まれないことを先に確認します。元の Diff を安全に作成できない項目は、位置と理由だけを記録し、秘密の値を出力しません。
