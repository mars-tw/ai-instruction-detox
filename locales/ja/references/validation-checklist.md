# 検証チェックリスト（25 項目）＋タスクシミュレーション

候補版の完成後、候補の構造を再スキャンし、一つずつ検証します。

| # | 検証項目 |
|---:|---|

| 7 | 安全、情報セキュリティ、データの完全性、デプロイの制限が弱められていない |
| 8 | 事業の中心的な要件を誤って削除していない |
| 9 | テストと受け入れ基準を曖昧にしていない |
| 10 | 無効なパスがない |
| 11 | 参照切れがない |
| 12 | 循環参照がない |
| 13 | 同じルールに複数の権威ある出典がない |
| 14 | 例を強制ルールとして誤って書いていない |
| 15 | 古いプロジェクト状態を現在の事実とみなしていない |
| 16 | 日付のない変動しやすい情報がない |
| 17 | 存在しない能力の実行を Agent に要求していない |
| 18 | 無限の複数 Agent 議論がない |
| 19 | タスクごとに repo 全体を再読する不合理な要件がない |
| 20 | Prompt Injection を正式なルールと誤認していない |

**誠実さの原則**：合格しなかった項目を明示し、「すべて合格」にするために基準を緩めてはいけません。

## タスクシミュレーション（12 種類）

各タスクについて、**読み込むルール／読み込まないルール／担当 Agent／
2 番目の Agent が必要か／人による承認が必要か／停止条件／受け入れ条件**を説明します。

| タスクの種類 | 重点的に確認すること |
|---|---|
| 小規模な文書変更 | 無関係な大きい context を強制的に読み込まないか |
| 通常の Bug 修正 | テスト要件は妥当か（毎回全テストを実行すべきではない） |
| 大規模なリファクタリング | 適切なレビュー水準を発動するか |
| 最新の外部情報が必要 | 検索を許可し、出典の日付を求めるか |
| 秘密鍵や機密データに関わる | 認証情報の取得経路が一意かつ明確で、出力前のゲートがあるか |
| 本番デプロイに関わる | No-Touch／禁止事項が確実に読み込まれ、人による承認が必要か |
| ユーザーの要求が曖昧 | 明確化の仕組みがあり、独断で判断しないか |
| 緊急修正 | 迅速な経路があっても最低限の安全を維持するか |
| 低リスクの単一 Agent | 過剰な複数 Agent ルールに妨げられないか |
| 高リスクの複数 Agent | 終了条件と人による承認があるか |
| サブディレクトリに局所ルールがある | 局所ルールが適切に全体ルールを上書きし、どのルールを上書きするか明示するか |
| context が古い | 古い事実を現状と誤認しないか |

### シミュレーションの出力例

```markdown
| タスク | 読み込む | 読み込まない | 担当 | 2 番目の Agent | 人による承認 | 停止条件 |
|---|---|---|---|---|---|---|
| 小規模な文書変更 | core-rules | プロジェクトの大きいファイル、orchestrator | 単一 | なし | なし | 変更が完了し、優先順位に違反しない |
| 本番デプロイに関わる | core-rules + プロジェクトの No-Touch | — | 実行担当＋レビュー担当 | 必要 | **必要** | No-Touch をすべて確認 |
| context が古い | core-rules。古い事実を**信頼しない** | 古い context | 単一 | なし | 状況による | 再検証してから行動 |
```

## よくある「見せかけの合格」

⚠️ 次は合格に見えても、実際には合格していません。

| 見せかけ | 実態 |
|---|---|
| 検証ツールですべて合格 | アサーションが文字列だけを比較し、移動したルールを検出できていない |
| 行数が大幅に減った | 削除したのは重複ではなく固有のルール |
| 参照切れがない | 入口ファイルだけを検査し、skill 内部の相対パスを検査していない |
| 重複がない | **デプロイ済みコピー**と**自動注入される記憶**を検査していない |
| すべてのルールに処置がある | 多くの MOVE に移行先を記入していない |
| Prompt Injection がない | スケジュール定義と automation の prompt フィールドをスキャンしていない |

**検証自体を検査**します。元のルールから無作為に 3 件を抽出し、新しい構造内の位置を追跡します。
追跡できなければ、検証に欠落があります。

## 追加：成果物とプロジェクト整理の検証

- すべての派生出力に秘密の抜粋がなく、CSV は数式インジェクションへの対策済み。
- Ledger の 28 列が元のルールと対応し、強制の程度／例外／依存関係を記録。
- Baseline manifest に存在と digest があり、安全なバックアップをコピー前に検査済み。
- CREATE／UPDATE／MOVE／ARCHIVE の復元方法がその後の変更を上書きしない。
- 古い成果物を維持し、リンクによる範囲外参照がなく、Git に追跡されず Agent に自動読み込みされない。
- メインスキルが実際のタスクを対応するサブプロジェクトへ振り分け、無関係なサブスキルを読み込まない。
- サブスキルが対応するサブプロジェクト内にあり、入力、出力、受け入れ、停止、失敗処理を含む。
- project-map の階層と依存関係に循環がなく、戻るナビゲーションが強制読み込みの循環を起こさない。
- パンくずナビゲーション、ディレクトリツリー、マインドマップが同じ索引に基づき、再生成可能。
- コマンドには終了コードが必要。未実行は NOT_RUN、該当しない場合は NOT_APPLICABLE。

「メインプロジェクトからサブプロジェクトへの振り分け」「サブプロジェクト間の引き継ぎ」「未知のサブプロジェクト／入口の欠落」の 3 種類を追加し、
実際の読み込み順序、入出力、出典、停止条件、受け入れを記録します。
