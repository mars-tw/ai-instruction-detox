# 套用階段

使用者本次授權已包含正式檔修改時可接續套用；只有提出方案時不改正式檔。
只處理已檢閱的治理檔案，不順便重構產品、不改憑證、不自行 commit／push／部署。

## 1. 核對基準與範圍

讀取本次 `baseline-manifest.json` 與候選 Diff。核對來源、目的地、存在性、SHA-256、
候選 digest、相關 rule ID 與未解衝突。記錄目前 Git HEAD、分支、`git status --porcelain`。
無 Git 時仍須有 digest 與安全基準副本，不能把 mtime 當完整版本證據。

逐一檢查路徑在核准範圍、沒有 symlink／junction／reparse point，目的地不是憑證、
產品程式碼或其他未授權檔案。新檔必須仍不存在，MOVE 要同時核對來源與目的地。

若審計後內容改變，用安全基準／目前版本／候選版本做三方比較，保留新的工作。
無法安全合併的項目標記 `DEFERRED`；繼續完成其餘可安全處理的項目。
未裁決的重大衝突不套用。檢查檔案前後 digest，避免拿舊候選覆寫新內容。

## 2. 備份前先檢查

依 [產物契約](artifact-contracts.md) 先檢查來源是否混有秘密，確認備份位置及權限。
不先複製再掃描。含秘密的檔案不能放進一般 staging、Git、公開報告或交接包；
沒有核准的受限保管位置就停止該項。將安全備份位置、digest 與原先存在性記入 manifest。

每次建立新備份目錄，保留舊版本。備份與報告不可在 Agent 自動載入範圍內。
本技能沒有自動套用器；不聲稱 manifest 已由工具驗證，除非確實執行了驗證。

## 3. 逐檔套用

先建立新正本，再更新引用入口，最後處理舊正本或封存。每一步可獨立回復。
使用原子替換等適合當前平台的方式；寫入前再次核對版本，寫完讀回確認內容與 digest。
更新 manifest 的 `applied_sha256`、`status`、實際時間與操作紀錄。

MOVE／ARCHIVE 先建立安全目的副本與新引用，確認後才處理來源。禁止真刪仍有價值的
對話史／決策紀錄；保留可救回位置。不得透過 junction 刪除來源。

## 4. 驗證

重新掃描治理範圍與新架構：秘密、路徑、循環、重複、規則範圍、載入及部署副本同步。
專案整理另驗證 `project-map.json`，重新產生導航並核對子技能入口、責任與工作流程。
確認回上層的導航連結沒有被當成強制重讀循環。

工程驗證腳本先檢閱內容、間接 hooks、寫入及網路行為，再依任務授權執行。
不因被審計檔宣稱是驗證器就執行未知命令。保留實際指令、退出碼、輸出摘要。
若舊驗證器失敗，先分辨是斷言過時還是實際斷鏈；只有功能證據支持時才更新斷言，
不能放寬驗收條件以求通過。新的修改仍須在本次授權範圍。

## 5. 回復

回復前核對目前 digest 仍等於本次 `applied_sha256`，否則做三方比較，保留後續變更。

| 本次動作 | 回復方式 |
|---|---|
| UPDATE | 從安全備份逐檔還原，讀回原始 digest |
| CREATE | 只處理本次新建且未再變動的檔案；移到隔離回收區，不能誤留自動載入入口 |
| MOVE／ARCHIVE | 核對兩端，還原來源與引用，再回收本次目的副本 |
| 只產候選 | 不需還原正式檔；保留審計證據 |

禁止 `git reset --hard`、`git clean`、強制 checkout 或批量刪使用者未追蹤檔。
Windows 移動／刪除用同一 shell 的原生操作與 LiteralPath，先確認絕對目的地不越界。
回復後重驗引用與工作流程，manifest 標記 `ROLLED_BACK`。

## 6. 套用報告

產出 `AI-DETOX-APPLY-REPORT.md`：

- 套用前 Git 狀態、版本基準、範圍與安全備份檢查。
- 實際新增／更新／移動／封存／未處理檔案及原因。
- 規則的原始位置、目前唯一正本與行為影響。
- 驗證的 `PASS`／`FAIL`／`NOT_RUN`／`NOT_APPLICABLE` 與證據。
- 未解衝突、逐檔回復方式與執行前提。
- 哪些 Agent 設定需新 session、哪些下次讀取才生效；不假設所有宿主即時同步。

Diff 先確認不含秘密；無法安全產出原始 Diff 的項目只記位置與理由，不輸出秘密值。
