# 套用階段（AI-DETOX APPLY）

**只有用戶明確要求套用時才進入。** 審計階段一律不改原檔。

```
MODE = APPLY
GIT_COMMIT = DENIED
GIT_PUSH = DENIED
DEPLOYMENT = DENIED
PRODUCT_CODE_REFACTOR = DENIED     # 只改 AI 指令治理範圍內的檔
SECRET_FILES_WRITE = DENIED        # 不動 .env／密鑰／token／連線資訊
DESTRUCTIVE_GIT = DENIED           # 不 reset／clean／強制 checkout／刪未追蹤檔
```

---

## 套用順序

### 步驟 1：重新檢查現況（必做）

```bash
git status --porcelain | wc -l          # 與審計時比對
git rev-parse --abbrev-ref HEAD
```

比對每個目標檔的 mtime 與 hash 是否仍與審計時一致。

**若正式檔案與審計時版本不一致**：
1. **不要強行覆蓋**
2. 先做**三方比較**（審計時版本／目前版本／候選版本）
3. **保留新變更**
4. 無法安全合併的部分 → 列入人工裁決
5. **繼續完成其餘可安全處理的項目**（不要因為一項卡住就整批放棄）

**若 git status 有新增變更**：查明是什麼。若屬產品程式碼或工作目錄 → **一律不碰**。

### 步驟 2：對照審計文件

| 對照 | 確認什麼 |
|---|---|
| `01-rule-ledger.csv` | 每條規則都有處置與追蹤位置；MOVE/MERGE 都有目標位置 |
| `02-conflicts-and-precedence.md` | **仍標記未裁決的重大衝突一律不套用** |
| `03-delete-merge-move.md` | 只處理已明確列入候選方案的項目 |

### 步驟 3：時間戳記備份

```bash
BAK=".../backups/ai-detox-apply-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$BAK"
# 只備份要改的 AI 指令檔
```

**備份後必須掃描備份區確認沒有密鑰被複製到不安全位置**：

```
sk-[A-Za-z0-9_.-]{20}    cfk_[A-Za-z0-9]{20}    GOCSPX-
ghp_[A-Za-z0-9]{20}      -----BEGIN .*PRIVATE KEY
1//0[A-Za-z0-9_-]{30}    ://[user]:[pass]@
```

⚠️ 用可靠方式判斷結果——`if grep ... | head` 的結束碼會被 `head` 影響而誤報。

### 步驟 4：逐檔套用

建議順序（每步可獨立回復）：
1. 先建**新增檔案**（共用正本），不覆蓋任何既有檔
2. 再改**影響最小**的入口檔
3. 最後改**影響最大**的（例：消除大型雙份檔）

每改一個就驗證一次，不要全部改完才驗。

### 步驟 5：套用後完整重新掃描

```
[ ] 懸空引用（檔內所有路徑逐一 test -e）
[ ] 循環引用（誰讀誰有向圖找環）
[ ] 重複規則（關鍵規則字串應只在正本出現）
[ ] 作用範圍（規則是否落在正確層級）
[ ] Prompt Injection（新檔是否引入可疑指令）
[ ] 秘密外洩（新檔不得含任何密鑰值）
```

### 步驟 6：執行設定相關驗證

跑專案既有的同步驗證腳本。

⚠️ **若驗證器變紅，先判斷是哪一種**：
- **斷言過時**（規則搬家了、字面比對失效）→ 更新斷言
- **規則真的斷鏈**（引用指向不存在的東西）→ 修規則

**不要為了讓驗證器變綠而把規則搬回舊位置。**
確認功能面完好後才更新斷言，並在報告中說明「這是主動擴大的修改範圍」。

**不得部署正式環境。**

### 步驟 7：產出

- 套用前後 **Unified Diff**
- **`AI-DETOX-APPLY-REPORT.md`**

## 最後一項最容易被忘記

**入口檔幾乎都是 session 啟動時載入的。** 套用完成 ≠ 立即生效。

必須明確告訴用戶：
- 哪些檔案改了要重啟才生效
- 哪些是即時生效（例：每次執行才讀的腳本）
- 現在這個 session 仍然持有舊內容

---

## 絕不可做

- 自動 git commit
- 自動 push
- 自動部署
- 自動安裝套件
- 修改 `.env`／密鑰／token／憑證／正式環境連線資訊
- `git reset` / `git clean` / 強制 checkout / 刪除未追蹤的使用者檔案
- 順便重構產品程式碼
- 覆蓋用戶在審計後新增的變更
- 為了降低 Token 數而刪除仍有商業或驗收價值的規則
