# 目標架構：清理後長什麼樣

---

## 四條鐵律

### 1. 單一權威來源

每一條規則只能有**一個**主要權威來源。其他檔案只能：
引用／做 Agent-specific 轉接／補充真正不同的範圍。

**不要**在入口檔、skills、context 各複製一份相同規則。

### 2. 入口檔只放長期全域規則

應該放：
- 專案使命與範圍
- 不能破壞的核心限制
- 重要架構原則
- 安全與資料保護
- 主要開發指令
- 測試與驗收最低要求
- 變更與部署邊界
- 指令優先順序
- 如何載入相關 skill／context
- 完工定義

**不應該**放：
大量歷史紀錄／單次事故／特定任務完整流程／大量範例／
已結案 Phase 細節／每次任務都不需要的背景／頻繁變動的人員與版本資訊

軟性目標 **80–200 行**。超過時說明原因，**不是為了達標硬刪重要內容**。

### 3. skills 只放可重複使用的工作流程

每個 skill 應包含：名稱／目的／觸發條件／不該觸發的情況／必要輸入／
可用工具／執行步驟／風險與限制／輸出格式／驗收標準／停止條件／
失敗處理／與其他 skill 的關係。

**不得讓所有 skill 每次都自動載入**，只載入與當前任務直接相關的。

### 4. context 只放事實與狀態

應保存：已驗證事實／架構狀態／專案基準／目前版本／已完成與未完成項目／
名詞表／角色與資源／決策依據／來源與日期。

**不應**塞入大量永久行為規則。

易變資訊必須帶：
```yaml
verified_at: 2026-08-27
source: <實測方式或出處>
owner: <負責人>
expires_at / recheck_condition: <重驗條件>
```

## 跨 Agent 共用架構

**問題**：不同 Agent 入口檔不同，且不一定支援相同的引用語法。

**方案**（不假設任何工具支援特定引用語法）：

```
<共用目錄>/core-rules.md          ← 純文字，任何 Agent 都能讀
├── 規則優先序
├── 語言
├── 憑證
├── 對外文案政策
├── 跨 CLI 派工
└── 不得聲稱未發生的事

各 Agent 入口檔（只留該 Agent 真正的差異）
├── Claude:  用該工具支援且已驗證可用的 import 語法
├── Codex:   明確路徑載入指令（「載入並遵循 <path>」）
├── Qwen:    同上
└── Grok:    同上
```

**關鍵**：
1. 先**檢查目前環境與專案實際使用方式**，不要假設語法可用。
2. 若工具不支援引用，只重複**無法避免的最小內容**。
3. 對重複部分**建立同步驗證**（見下）。
4. 各入口檔加 `VERSION` 標記，供比對是否分裂。

---

## 一次性事故該去哪

| 性質 | 去處 |
|---|---|
| 可自動驗證的行為 | regression test |
| 交付前必查 | acceptance checklist |
| 架構決策 | ADR（Architecture Decision Record） |
| 事故經過與根因 | incident report |
| 為何這樣決定 | decision log |
| 純歷史 | archive（不再載入） |
| 只在某目錄成立 | 該目錄的規則檔 |

**不要把所有事故永久堆進全域 Agent 指令。**

---

## 規則寫法

每條規則盡可能包含：**動作／適用範圍／觸發條件／例外／驗證方式／失敗時處理**。

少用沒有判斷標準的詞：最好／完美／高品質／自然／適當／視情況／最新／優先／完整。

對 `MUST`／`NEVER`／`ALWAYS` **特別審查**——只有真正不可違反的
安全、資料完整性、法規或核心驗收條件才配用絕對詞。

---

## 防止規則再次堆積

1. **單一權威來源原則**寫進入口檔本身
2. **入口檔行數軟上限**（使用者層 ≤ 40 行、專案層 ≤ 200 行）
3. **同步檢查自動化**：寫一支腳本驗證
   - 各入口檔是否都指向共用正本
   - `VERSION` 是否一致
   - 關鍵規則字串是否只出現在正本（無重複）
   - 引用路徑是否都存在（無懸空）
4. **新增規則前先問三題**：
   - 正本在哪？（是否已經有人寫過）
   - 可否自動驗證？（能的話寫成測試）
   - 是通用原則還是一次性事故？（後者縮範圍）
5. **記憶與排程納入季度審查**——這兩類會自動注入，最容易累積過時規則

---

## 同步驗證腳本應該檢查什麼

```
[ ] 共用正本存在且非空
[ ] 共用正本含所有必要章節
[ ] 每個入口檔都指向共用正本
[ ] 入口檔沒有複寫正本內容（關鍵字串不重複出現）
[ ] 所有引用路徑存在（無懸空）
[ ] 沒有循環引用
[ ] skill 連結／junction 指向正確目標
[ ] 已部署副本與原始 assets 同步（hash 比對）
```

⚠️ **驗證腳本自己也會過期**：若它用「字面比對」檢查入口檔內容，
規則搬家後會誤紅。修的時候要先確認**是斷言過時、還是規則真的斷鏈**。
建議斷言驗證「**功能**」（是否指向正本）而非「**字面**」（是否含某句話）。
